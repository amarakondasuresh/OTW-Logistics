ADMIN LOGIN SETUP - IMPORTANT

1. Extract this ZIP into a NEW folder (do not mix it with an older project folder).
2. Run START-WINDOWS.bat once and wait for the server/dependencies to initialize.
3. Stop the server window with Ctrl+C.
4. Run SETUP-ADMIN-LOGINS.bat ONCE.
5. The script generates four fresh random temporary passwords, writes their credentials to
   backend\\ADMIN-TEMPORARY-LOGIN-CREDENTIALS.txt, and verifies each password against the
   salted scrypt hash saved in this same folder's backend\\payments.sqlite database.
6. Restart START-WINDOWS.bat and sign in at http://localhost:8080/dashboard/.
7. Each admin must choose a new password at first sign-in.

IMPORTANT:
- Use the credentials file generated by the most recent setup run. Do not use passwords from
  an older ZIP, an old screenshot, or a previous credentials file.
- Do not run SETUP-ADMIN-LOGINS.bat again after admins have chosen their own passwords:
  running it again intentionally resets all four passwords.
- If an old server is still running from a different extracted folder, stop it first. The
  browser must connect to the server/database in this newly extracted folder.
- Plaintext temporary passwords exist only in the local credentials report and terminal output.
  Keep that report private and delete it after sharing each admin's own credentials.
- Passwords in SQLite are stored as salted scrypt hashes, never plaintext.

FORGOT PASSWORD:
The reset flow is implemented, but reset emails require valid Gmail App Password or SMTP
settings in backend\\.env. Configure GMAIL_USER and GMAIL_APP_PASSWORD (Google App Password,
not the normal Gmail password), or SMTP_HOST/SMTP_USER/SMTP_PASS, then restart the backend.
Without mail configuration, the page cannot deliver reset links. Check the server terminal
for "Password reset email failed" if delivery is not configured.
